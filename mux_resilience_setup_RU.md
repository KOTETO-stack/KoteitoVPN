# Устойчивость соединения при потере пакетов / переключении сетей

Это и есть по сути та "защита от потери данных", которую обычно ищут в WARP —
только WARP у нас сознательно не используется (см. README_RU.md), а нужный
эффект (не терять сессию при скачке Wi-Fi ⇄ мобильная сеть, не рвать соединение
на мелких потерях пакетов) даёт правильная настройка самого клиента.

ЧЕСТНО: это не поле в самой ссылке `vless://`/`trojan://`/`hysteria2://` — вписать
туда несуществующий параметр означало бы риск, что Karing не разберёт ссылку
вообще. Это настройка уровня приложения, применяется сразу ко всем серверам
подписки.

## Что включить в Karing

1. Открой Karing → **Settings → Connection** (или "Настройки → Соединение").
2. **Mux (мультиплексирование)** → включить. Это держит несколько логических
   потоков в одном TCP/TLS-соединении — при коротком сбое сети сессия не
   пересоздаётся с нуля, а восстанавливается быстрее.
3. **TCP Keep-Alive** → включить, интервал 30 сек (по умолчанию в Karing обычно
   и так включено, но стоит проверить).
4. **Auto-reconnect on network change** ("Переподключение при смене сети") →
   включить — это именно то, что предотвращает "потерю данных" при переходе
   Wi-Fi → мобильная сеть.

## Для Hysteria2 отдельно

Hysteria2 поверх QUIC по протоколу устойчивее к потере пакетов, чем TCP
(QUIC изначально спроектирован для мобильных сетей с нестабильным
соединением) — так что для Hysteria2-серверов из подписки это уже работает
"из коробки" на уровне протокола, без дополнительных настроек.
